# 設計思想

## 構造は推測するものではなく、名付けるもの

多くの言語は、インデントから構造を推測し、括弧の数を数え、名前のない`end`を
追うことを読み手へ要求します。Separanではブロックに人間が読める名前を与え、
その名前自体を構文にします。

ラベルはコメントではありません。ASTに保持され、構文検証に使われ、将来は移動、
レビュー、リファクタリング、AI編集のための安定したハンドルになります。

Separanは、人間もコード生成器も間違えることを前提にします。曖昧な構造、危険な
暗黙変換、古くなったラベルを可能な限り早く拒否し、人間が修正できる言葉で原因を
説明することが処理系の仕事です。

目的は文字数を減らすことではありません。不確実性を減らすことです。

この原則は型変換にも適用します。値の型を変える判断は、`number(...)`、
`string(...)`、`boolean(...)`としてソース上に現れなければなりません。
Separanは暗黙変換とtruthy/falsyを拒否します。便利な曖昧さも曖昧さだからです。

時間にも同じ原則を適用します。瞬間、ゾーン未確定の壁時計日時、タイムゾーン、
経過時間を、1つのstringや単位のないnumberへ押し込みません。採用済みの
[v0.2時間型設計](../spec/temporal-types.ja.md)では、それぞれを個別の型として
名付けます。

乱数も用途を名乗らなければなりません。再現可能なシミュレーション用乱数と
暗号学的乱数は、異なる関数群、状態、保証を持ちます。レビュー時にソースを見れば
どちらを使っているか分かる設計にします。
